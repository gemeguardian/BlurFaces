# Blur Faces — план устранения мерцания и лага блюра

**Цель:** блюр должен двигаться вместе с лицом, не мерцать, не пропадать, с минимальной задержкой.

**Текущий статус:** блюр работает, но мерцает и отстаёт. Нативный краш в 1.3.7 — отдельный блокер, но даже при рабочей инициализации архитектура не даёт нужного качества.

---

## Диагноз: почему мерцает и лагает

1. **Детекция на каждом кадре через glReadPixels.** `glReadPixels` — синхронная операция, она читает уже отрендеренный кадр. Пока SCRFD обработает его (десятки-сотни мс), лицо уже сдвинулось. Блюр рисуется по устаревшим координатам.

2. **Нет трекинга.** SCRFD — детектор, не трекер. Каждый кадр он ищет лицо заново. На быстром движении детектор то находит, то теряет лицо — отсюда мерцание.

3. **FACE_HOLD_MS = 120 мс.** Слишком короткое окно. Если детекция занимает >120 мс (а SCRFD-10G на CPU — да), лицо «истекает» до прихода нового результата.

4. **Детекция на разных поверхностях.** Preview (1328×1328), encoder (448×448), мелкие сурфейсы (48×48) — все шлют результаты в одни глобальные `faceRects`. Мелкие сурфейсы дают шум и затирают валидные координаты.

5. **Velocity prediction слишком слабый.** `factor` ограничен 1.0, при быстром движении предсказание отстаёт. Нет сглаживания — блюр дёргается.

6. **Нет расширения бокса.** Блюр применяется точно по bbox. Малейшая ошибка детекции/предсказания — и край лица виден.

## План исправления (без переписывания архитектуры)

### Этап 1: Убрать мерцание (быстрый фикс)

**Файл:** `src/main/java/com/makey/blurfaces/Main.java`

1. **Увеличить FACE_HOLD_MS до 500 мс.** Даёт запас на медленную детекцию.
2. **Не сбрасывать faceCount по таймауту, а плавно уменьшать.** Вместо `faceCount = 0` — постепенно уменьшать alpha/размер блюра в течение 200 мс.
3. **Добавить One Euro Filter или экспоненциальное сглаживание** для координат. Убирает дёрганье.
4. **Расширить бокс на 20%** в шейдере или в Java перед передачей в uniforms. Компенсирует ошибки трекинга.
5. **Игнорировать результаты с поверхностей < 256×256** (уже есть, но усилить — не публиковать результаты с 48×48 вообще).

### Этап 2: Убрать лаг (средний фикс)

**Файл:** `src/main/java/com/makey/blurfaces/Main.java`

1. **DETECT_INTERVAL = 2 или 3.** Не каждый кадр — каждый 2-3-й кадр. Снижает нагрузку, но требует лучшего предсказания.
2. **Улучшить velocity prediction:**
   - Убрать ограничение `factor <= 1.0`, разрешить экстраполяцию до 1.5×.
   - Добавить acceleration (вторая производная) если есть 3+ точки.
3. **Добавить Kalman filter** для каждого лица (состояние: x, y, vx, vy). Даёт плавное и предсказуемое движение.

### Этап 3: Правильная архитектура (долгосрочный фикс)

**Файлы:** `Main.java`, `NativeBridge.java`, `main.cpp`, `scrfd.cpp`

1. **Захватывать кадры до рендеринга**, не через glReadPixels:
   - Хук на `SurfaceTexture.updateTexImage()` или `CameraGLThread` — получить `SurfaceTexture` и его `stMatrix`.
   - Или хук на `GLES20.glUniformMatrix4fv` когда ставится `uSTMatrix` — перехватить трансформ.
2. **GPU-based readback:** создать свой FBO, рендерить OES-текстуру в него, читать из FBO (быстрее, чем из default framebuffer).
3. **Легковесный трекер на каждом кадре:**
   - SCRFD запускать раз в N кадров (например, 10) для инициализации/восстановления.
   - Между детекциями — optical flow (Lucas-Kanade) или template matching на GPU/CPU.
4. **Использовать stMatrix для точного маппинга** координат камеры в UV шейдера.

## Проверка

- Логи: `detect frame N: M faces (WxH)` — должны быть стабильные W×H (только camera surfaces).
- Визуально: блюр следует за лицом без мерцания, без отставания при быстром движении.
- Записанное видео: блюр присутствует на всех кадрах, где видно лицо.

---

## Риски

- Увеличение FACE_HOLD_MS может оставлять блюр на пустом месте, если лицо быстро ушло из кадра.
- Сглаживание добавляет инерцию — при резком движении блюр может «догонять» лицо.
- Kalman filter требует тюнинга параметров (process noise, measurement noise).
