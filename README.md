# Blur Faces 1.0.0

Плагин exteraGram для скрытия голов в превью камеры **кружков** и записываемых видеосообщениях. Android, **arm64-v8a**. Минимальные версии в метаданных: exteraGram 12.5.1 и SDK 1.4.4.3. Совместимость конкретной сборки клиента необходимо проверять на устройстве: используются внутренние camera/encoder hooks.

## Как работает

- YOLOv8n-Head, вход 320×320, NCNN на CPU, два потока.
- Native ByteTrack подтверждает головы и поддерживает треки при кратких пропусках.
- Java сглаживает подтверждённую геометрию и использует оптический поток. Повторного порога уверенности в Java нет.
- OpenGL накладывает Gaussian blur, пикселизацию или сплошную маску на превью и encoder frames.
- В темноте применяется CLAHE по яркости с временным EMA и адаптивными native-порогами.

Настройки: размытие по умолчанию, стиль маски, чувствительность 35/25/18%. Размер маски фиксирован на 100%, разрешение кружка выбирает хост. В камере есть ручной переключатель защиты.

## Приватность и ограничения

**Сеть не нужна, включая первый запуск.** DEX, ARM64 ELF, `head_det.param` и `head_det.bin` входят в `.elyx`. Загрузчик проверяет SHA-256 и копирует ресурсы в закрытый каталог приложения; дерево Elyx assets не изменяется.

По умолчанию чистые кадры не сохраняются. **Debug-захват включается вручную** в настройках: он сохраняет неразмытые кадры и кропы (см. ниже). При запуске удаляются только старые JPEG с именами формата Blur Faces из `files/blurfaces_storage`; посторонние файлы и ссылки не затрагиваются. Ошибка удаления записывается в лог. Это обычное удаление, не гарантированное стирание данных с флеш-памяти.

Ошибка native-инференса, некорректная геометрия или превышение лимита четырёх масок не считаются пустой сценой: включается полнокадровая защита до свежего успешного результата. Смена камеры сбрасывает очередь и треки; поздние результаты до переключения отбрасываются.

Это **не гарантия анонимности**: модель может пропустить голову, а размытие не исключает узнавание по другим признакам. Нет подтверждённых замеров 8–10 мс, стабильных 30–60 FPS или нулевых ложных срабатываний для текущей сборки. Если плагин не загрузился или хуки несовместимы с клиентом, нельзя считать камеру защищённой. CPU-самотест маски не проверяет нейросеть, GPU или итоговый видеопоток.

После обновления DEX/нативной библиотеки перезапустите exteraGram. Подмена загруженного native runtime без перезапуска отклоняется. Копии ресурсов в закрытых каталогах приложения могут сохраняться после удаления плагина; полная автоматическая очистка runtime-кэшей не заявляется.

## Локальный debug-захват

В настройках включите «Сохранять debug-кадры · 5 минут» **только с согласия людей в кадре**. Затем воспроизведите ложное срабатывание или пропуск. «Обновить статус и показать путь» выводит состояние, число/объём архивов, оставшееся время и закрытый каталог `no_backup/blur_faces_debug` приложения. Плагин ничего не отправляет; забрать ZIP можно локально через разрешённый root/SSH-доступ.

- До 2 образцов/с, один фоновый writer, без неограниченной очереди; лимит 300 ZIP или 32 МиБ может остановить запись раньше пяти минут.
- Запись выключается через 5 минут, при выгрузке/перезагрузке плагина и перезапуске приложения. **Файлы при этом остаются.** Кнопка удаления останавливает запись и удаляет её файлы. Записи старше суток очищаются при следующей настройке debug/запуске runtime, не отдельным круглосуточным таймером.
- Каждый ZIP содержит `frame.rgba`: исходный downsample 192×192 RGBA8888 с верхним левым началом координат, после вертикальной коррекции PBO и до CLAHE; `candidate_*.jpg`, `track_*.jpg` с контекстом 25%; `metadata.json`.
- JSON связывает bundle hash, источник камеры, capture/result timestamps, задержку, пороги/яркость, кандидатов **после фильтров/NMS**, native observed/predicted tracks (`frames_lost`) и Java-геометрию/возраст треков. Java snapshot не вызывает prediction и не меняет сглаживание.
- Есть кандидат на постороннем объекте — проверяем детектор; кандидата нет, но есть `predicted_track` — native coasting; native треков нет, но есть `java_tracks` — Java удержание. Один образец не заменяет последовательность кадров.
- Это не сегментационные маски нейросети и не снимок финального шейдера: модель выдаёт рамки. Геометрия JSON позволяет разбирать треки, но итоговые preview/encoder masks требуют отдельной проверки видеопотока. Пропуски ниже low threshold/geometry filters в списке кандидатов не видны; для визуального разбора сохранён полный кадр.

## Сборка и установка

Нужны JDK 17+, Android SDK/NDK, локальные NCNN binaries, `elyb` и оба файла модели в `models/`.

```bash
./build.sh
```

Скрипт принимает `JAVA_HOME`, `ANDROID_NDK_ROOT` и `ELYX_BUILDER`. Результат: `builds/blur_faces-1.0.0.elyx`. Откройте его в exteraGram и включите плагин. Веса (~5,8 МиБ до сжатия) уже внутри архива.

## Проверки

Из корня проекта, после сборки:

```bash
JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ./gradlew testReleaseUnitTest
PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -p no:cacheprovider tests/tests_*.py
python3 tests/tests_tracking_behavior.py
python3 tests/tests_elyx_contract.py
```

- JUnit выполняет настоящий Java-код трекинга, обработки ошибок, оптического потока и debug-хранилища (лимиты, срок сессии, удаление, защита от старых writer-заданий). Android API в JVM-тестах — stubs, не реальное устройство.
- `python3 scripts/test_debug_device.py --host phone` после сборки выполняет standalone Android-тест на искусственных кадрах: реальные ES3/PBO, JPEG/JSON/ZIP, фоновое сохранение и NCNN/JNI. Камера не открывается, установленный плагин не меняется; нужны разрешённый SSH-доступ и `app_process`. Результат записывается в `build/device-test/result.txt`.
- `tests_native_behavior.py` компилирует настоящий C++ ByteTrack и политику обработки результатов JNI с UBSan; нужен `g++` или `CXX`. NCNN-инференс этим тестом не выполняется.
- Python-тесты выполняют функции загрузчика: автономное копирование, проверка хэшей, восстановление кэша, отказ при повреждённой модели и очистка старых кадров.
- Packaging contract сравнивает Python, DEX, ELF и **оба** файла модели с существующим `.elyx`.
- Старый `tests_tracking_behavior.py` — дополнительная математическая модель, не замена production-тестам.

Перед выпуском обязательна [проверка на телефоне](DEVICE_VALIDATION.md), включая покадровый просмотр **записанного** кружка. `HANDOFF.md` содержит актуальную архитектурную сводку, а старый план перехода на YOLO помечен как исторический.
